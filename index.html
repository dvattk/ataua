AτA: A Benchmark for Multi‑Agent Interaction in Agentic Economies

Overview

This post covers our paper, AτA: A Benchmark for Multi-Agent Interaction in Agentic Economies. We build a simulator for studying multi-agent interaction in a realistic market, using the airline industry as a familiar domain that is easy to study. The market has two kinds of agents: a user agent acts on behalf of a traveler, and a provider agent acts on behalf of an airline.

Each user has a persona, preferences and a budget. A population of user agents interacts with the provider agents simultaneously, so many users shop at the same time from the same inventory, and every booking changes what is left for the others. Each provider agent sells its airline's seats under the airline's policy, deciding which offers to make and how much to concede on price.

How well do these agents serve both sides when many of them meet in the same market? To answer this, we need a simulator where we can study these interactions at scale. In the next section, we describe how we build it.

Building the market

The most important part of a market is the data behind it: provider inventory for the providers to sell, and diverse users who want to use the service. In AτA, providers sell from flight inventory built from real U.S. fare records, and users differ in their personas, preferences and budgets.

Provider inventory

Each airline provider maintains a flight database listing the routes it serves, departure and arrival times, fares, and the number of seats available in each cabin class. This inventory determines which flights a provider can offer and how many travelers it can serve. To build it, we take travel records between 20 U.S. airports from the BTS DB1B market survey and compute the median observed fare for each route and airline. We then generate flight schedules over a 30-day period, with fares based on these reference prices and adjusted for each cabin class. The resulting catalog contains 1,746 itineraries across 44 airports and 23 airlines.

Users: personas, emails and goals

Each user has a persona that shapes their preferences and budget, a target budget they would like to spend and a walk-away budget they will not exceed. Their preferences are not handed to the agent as a checklist. For every user we first fix a hidden profile of hard constraints (must hold) and soft preferences (can be traded off), then an LLM writes that user's own emails from it. The agent has to infer what is wanted and which requests are non-negotiable. A task puts five users with related trips into the market at the same time.

The 13 personas

Normal: budget conscious, premium traveler, business time-sensitive, price comparison, impulse buyer, flexible traveler, explicit explorer. Adversarial: fake loyalty, competitor anchor, pressure discount, social engineering, policy exploiter, info extraction. Adversarial personas stress-test provider agents against social attacks.

How emails are generated

An LLM turns each user's structured profile into an inbox of 20–30 emails, mixing travel threads, financial records and unrelated messages. Each inbox is reviewed against the source profile. The structured profile is withheld from the agent and kept for scoring.

A task puts \(m\) users on the same reference flight, so the space grows as \(F \times G^{m}\). For a pool of 20 users that is about \(10^{70}\) combinations. We evaluate a fixed sample of 100 tasks.

Supply: scarce or abundant

All users draw from the same inventory, so every booking removes a seat for everyone else. Under abundant supply there are more seats than users need. Under scarce supply, users compete for the options they prefer and some must compromise.

Agents: who trades with whom

Each of the N users has a user agent, and each of the K airlines has a provider agent. A user agent can contact any provider agent to ask for offers, compare them and negotiate price and services. It then picks an offer, and the provider agent books it under its airline's policy. There is no platform in between. This is the market in the animation at the top of the page.

Agent tools

User agents read the user's inbox and payment details, message provider agents and accept offers. Provider agents search their airline's inventory, quote fares within policy, apply discounts and add services, and make bookings.

Coordination modes

AτA also supports private channels between agents on the same side. In User Coordinate mode, user agents compare offers and coordinate their negotiations. In Provider Coordinate mode, agents for the same airline coordinate offers within inventory and policy. These channels are off in the main (BASE) runs.

Scoring both sides

We score each booking goal by user satisfaction and provider revenue, with both rewards in \([0, 1]\).

User reward

$$R_u = I_{\mathrm{pax}}\; C_{\mathrm{trip}}\; S_{\mathrm{budget}}\; S_{\mathrm{pref}}$$

The user reward combines passenger count, trip coverage, budget satisfaction and preference satisfaction. Because it is a product, a single failed factor sets the reward to zero.

User reward components

Passenger count, \(I_{\mathrm{pax}}\)

One if the booked passenger count matches the requested party size, zero otherwise. Travelers are deduplicated when a trip is split across several reservations.

Trip coverage, \(C_{\mathrm{trip}}\)

The share of everyone's required journeys that were booked, whether in one reservation or several. With party size \(n\), and \(n_{\mathrm{out}}\), \(n_{\mathrm{ret}}\) the travelers with a covered outbound and return journey:

$$C_{\mathrm{trip}} = \begin{cases} \dfrac{n_{\mathrm{out}}}{n}, & \text{one-way trip}, \\[6pt] \dfrac{n_{\mathrm{out}} + n_{\mathrm{ret}}}{2n}, & \text{round trip}. \end{cases}$$

Two people flying to Paris and back need four journeys. If one person's return is missing, \(C_{\mathrm{trip}} = 3/4\). Connecting flights do not add journeys; coverage checks that each traveler's flights connect the requested airports.

Budget satisfaction, \(S_{\mathrm{budget}}\)

Let \(c\) be net credit-card spending, \(B_{\mathrm{target}}\) the user's preferred budget and \(B_{\mathrm{walkaway}}\) the spending level at which satisfaction reaches zero:

$$S_{\mathrm{budget}}(c) = \begin{cases} 1, & c \le B_{\mathrm{target}}, \\[4pt] \dfrac{B_{\mathrm{walkaway}} - c}{B_{\mathrm{walkaway}} - B_{\mathrm{target}}}, & B_{\mathrm{target}} < c < B_{\mathrm{walkaway}}, \\[8pt] 0, & c \ge B_{\mathrm{walkaway}}. \end{cases}$$

Payments with certificates or gift cards do not count towards \(c\).

Preference satisfaction, \(S_{\mathrm{pref}}\)

Each traveler's ranked preferences are scored and weighted by inverse rank, so higher-priority requests count more, then averaged across the \(n\) travelers:

$$S_{\mathrm{pref}} = \frac{1}{n} \sum_{i=1}^{n} \frac{\sum_{d \in \mathcal{D}} w_d\, s_{i,d}}{\sum_{d \in \mathcal{D}} w_d}, \qquad w_d = \frac{1}{\tilde r(d)}$$

Here \(s_{i,d} \in [0, 1]\) is traveler \(i\)'s satisfaction on dimension \(d\), and \(\tilde r(d)\) is the dimension's rank, with tied dimensions sharing a rank. The dimensions are cabin class, routing, departure time, payment order, seat, checked bags, travel insurance, airline blacklist, meals and date flexibility.

Provider reward

$$R_{p,a} = \min\!\left(1, \frac{r_a}{R_a}\right), \qquad R_p = \frac{1}{|\mathcal{A}_{\mathrm{book}}|} \sum_{a \in \mathcal{A}_{\mathrm{book}}} R_{p,a}$$

Each airline's revenue from the user is compared with a reference revenue for that user's trip, and the provider reward averages this score over the airlines the user booked with.

Provider reward components

Booked airlines, \(\mathcal{A}_{\mathrm{book}}\)

The set of distinct airlines the user booked with. With one airline, \(R_p = R_{p,a}\). With no active booking, \(R_p = 0\).

Retained revenue, \(r_a\)

Airfare and paid extras from the user's active bookings with airline \(a\), including payments by certificates and gift cards. All of the user's reservations with that airline are summed before the cap. Discounts lower \(r_a\); paid services such as seats, meals, bags and insurance raise it.

Reference revenue, \(R_a\)

The airline's highest candidate fare across cabins for the reference trip, times the number of travelers, plus reference charges for seats, meals, baggage and insurance. It is a normalization reference, not the most the user could have paid.

Averaging

Each airline is capped at one separately and scored against its own full reference, so \(R_p\) reaches one only when every booked airline does. It measures average normalized airline performance, not total dollar revenue.

What is the best possible?

A reward of one is not always reachable: seats and budgets are limited. So for every task we search for the best complete allocation of seats to users, maximising a weighted mix of both rewards:

$$\lambda\, R_u + (1 - \lambda)\, R_p, \qquad \lambda \in \{0, 0.2, 0.4, 0.5, 0.6, 0.8, 1\}$$

Each weight gives one point. Sweeping λ from providers-only to users-only traces the MAX line, the reference every model is compared with below.

Solver details and caveats

The search lets every user move up to ±3 days, keeps preference penalties, and respects budgets and shared inventory. It covers all 100 tasks and seven weights per supply condition. Each point is a whole allocation. Solver time limits and the restricted search space mean MAX is the best found, not a proven upper bound.

Why the gap?

Individual decisions can undermine collective outcomes

Agent A booked the Delta seats, so Agent B settled for a pricier United trip. A coordinated allocation raises user reward from 0.88 to 0.93 and provider reward from 0.40 to 0.93.

Agents are good buyers but poor sellers

Provider agents could hold the fare, offer another cabin or add paid services. Instead, every booking received the full 30% discount, while customers spent only about half their budgets.

Takeaways

  • Agents complete bookings, markets fall short. No model reaches the MAX reference, under scarce or abundant supply.
  • Individual decisions can undermine collective outcomes. When seats are scarce, each agent's best move can take the option another user needed.
  • Agents are good buyers but poor sellers. Provider agents give away the full discount instead of using the other levers they have.
  • Price is not quality. A pricier provider agent does not reliably bring higher reward for either side.
