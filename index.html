Overview

This post covers our paper, AτA: A Benchmark for Multi-Agent Interaction in Agentic Economies, a simulator for studying multi-agent interaction in a realistic market.

In a real market, decisions do not happen in isolation. Many users with different preferences and budgets compete for limited inventory, while providers decide what to offer and at what price. Each transaction changes what remains available to others, making the outcome for any participant dependent on the decisions of others.

With AτA, we simulate these dynamics by bringing user agents and provider agents together in a shared market, each acting on behalf of the party they represent. We study how well agents achieve their respective objectives through these interactions and how their individual decisions shape outcomes across the market. In the next section, we describe how the simulator works.

Building the market

The most important part of a market is the data behind it: provider inventory for the providers to sell, and diverse users who want to use the service. In AτA, providers sell from flight inventory built from real U.S. fare records, while the users differ in their personas, preferences and budgets.

Provider inventory

Each airline provider maintains a flight database listing the routes it serves, departure and arrival times, fares, and the number of seats available in each cabin class. This inventory determines which flights a provider can offer and how many travelers it can serve. To build it, we take travel records between 20 U.S. airports from the BTS DB1B market survey and compute the median observed fare for each route and airline. We then generate flight schedules over a 30-day period, with fares based on these reference prices and adjusted for each cabin class. The resulting catalog contains 1,746 itineraries across 44 airports and 23 airlines.

User inventory

We create users with diverse personas, preferences and budgets. A persona shapes what a user wants. A budget-conscious user leans toward basic economy and a lower budget, while a premium user is more likely to prefer business class with a higher budget. Each user has a target budget, the amount they would prefer to spend, and a walk-away budget, the limit on their credit card.

Real travelers rarely state all of their preferences in a booking request. Much of it can only be inferred from their personal correspondence. We follow the same setup. Each user's preferences are fixed in a structured profile of hard constraints, which must be satisfied, and soft preferences, which allow compromise. For example, a user may refuse travel insurance but prefer layovers shorter than three hours. An LLM then writes the user's personal emails from this profile. The user agent sees only the emails, so it has to infer what the user wants and which requests are non-negotiable.

A task brings together \(\boldsymbol{N}\) users who interact with the providers at the same time. To build one, we sample a reference itinerary (a route and travel date) from the provider inventory and create each user's booking goal around it: the locations, dates and number of travelers. The users share a common travel context but differ in party size, cabin, date flexibility and return dates.

How large is the task space?

The inventory has 1,746 flights, each bookable on 14 dates, giving \(F = 1{,}746 \times 14 = 24{,}444\) flight–date options. Each user's booking is described by eight attributes:

Supply conditions

Real markets often face scarcity when demand exceeds the supply of preferred options. We consider two settings. Under abundant supply, supply substantially exceeds demand, so users can easily find options that match their preferences. Under scarce supply, limited availability creates competition for these options. For example, two users may want basic economy on the same flight, but the provider has only one such seat. One of them may then have to pay more for economy or look for another flight. In both settings users share the same inventory, so each booking reduces availability for the others.

How is scarcity generated?

For each task, we take every date within seven days of any user's departure or return date. On these dates, each flight and cabin gets a new number of seats, drawn from a Poisson distribution and capped at its original number of seats. The mean of the Poisson distribution depends on the cabin: 0.3 for basic economy, 0.6 for economy and 1.5 for business. All users of the task then book from this reduced inventory.

Evaluation

We score every booking goal from both sides, with each reward between 0 and 1.

User reward

The user reward asks one question: did the traveler get the trip they wanted, at a price they accept?

$$R_u \;=\; \underbrace{I_{\mathrm{pax}}}_{\substack{\text{passenger}\\\text{count}}}\;\times\;\underbrace{C_{\mathrm{trip}}}_{\substack{\text{trip}\\\text{coverage}}}\;\times\;\underbrace{S_{\mathrm{budget}}}_{\substack{\text{budget}\\\text{satisfaction}}}\;\times\;\underbrace{S_{\mathrm{pref}}}_{\substack{\text{preference}\\\text{satisfaction}}}$$

Because the four terms multiply, a missing traveler or a price at the walk-away budget sets the reward to zero, whatever else went well.

User reward components

Passenger count, \(I_{\mathrm{pax}}\)

One if the booked passenger count matches the requested party size, zero otherwise. Travelers are deduplicated when a trip is split across several reservations.

Trip coverage, \(C_{\mathrm{trip}}\)

The share of everyone's required journeys that were booked, whether in one reservation or several. With party size \(n\), and \(n_{\mathrm{out}}\), \(n_{\mathrm{ret}}\) the travelers with a covered outbound and return journey:

$$C_{\mathrm{trip}} = \begin{cases} \dfrac{n_{\mathrm{out}}}{n}, & \text{one-way trip}, \\[6pt] \dfrac{n_{\mathrm{out}} + n_{\mathrm{ret}}}{2n}, & \text{round trip}. \end{cases}$$

Two people flying to Paris and back need four journeys. If one person's return is missing, \(C_{\mathrm{trip}} = 3/4\). Connecting flights do not add journeys; coverage checks that each traveler's flights connect the requested airports.

Budget satisfaction, \(S_{\mathrm{budget}}\)

Let \(c\) be net credit-card spending, \(B_{\mathrm{target}}\) the user's preferred budget and \(B_{\mathrm{walkaway}}\) the spending level at which satisfaction reaches zero:

$$S_{\mathrm{budget}}(c) = \begin{cases} 1, & c \le B_{\mathrm{target}}, \\[4pt] \dfrac{B_{\mathrm{walkaway}} - c}{B_{\mathrm{walkaway}} - B_{\mathrm{target}}}, & B_{\mathrm{target}} < c < B_{\mathrm{walkaway}}, \\[8pt] 0, & c \ge B_{\mathrm{walkaway}}. \end{cases}$$

Payments with certificates or gift cards do not count towards \(c\).

Preference satisfaction, \(S_{\mathrm{pref}}\)

Each traveler's ranked preferences are scored and weighted by inverse rank, so higher-priority requests count more, then averaged across the \(n\) travelers:

$$S_{\mathrm{pref}} = \frac{1}{n} \sum_{i=1}^{n} \frac{\sum_{d \in \mathcal{D}} w_d\, s_{i,d}}{\sum_{d \in \mathcal{D}} w_d}, \qquad w_d = \frac{1}{\tilde r(d)}$$

Here \(s_{i,d} \in [0, 1]\) is traveler \(i\)'s satisfaction on dimension \(d\), and \(\tilde r(d)\) is the dimension's rank, with tied dimensions sharing a rank. The dimensions are cabin class, routing, departure time, payment order, seat, checked bags, travel insurance, airline blacklist, meals and date flexibility.

Provider reward

The provider reward asks: how much of the revenue this trip could bring did the airline actually earn?

$$R_p = \frac{1}{|\mathcal{A}_{\mathrm{book}}|} \sum_{a \in \mathcal{A}_{\mathrm{book}}} \min\!\left(1, \frac{r_a}{R_a}\right)$$

where

  • \(\mathcal{A}_{\mathrm{book}}\) is the set of airlines the user booked with.
  • \(r_a\) is what the user paid airline \(a\): fares plus paid extras, after discounts.
  • \(R_a\) is a reference revenue for the trip: airline \(a\)'s highest fare times the number of travelers, plus standard extras.

Each airline scores at most one, and the scores are averaged. Discounting too much or selling no extras lowers the reward.

Results

We evaluate frontier models from three families: GPT, Claude and Gemini. We run them in two settings. In the symmetric setting, the same model acts as both the user agents and the provider agents. In the asymmetric setting, the user agents and the provider agents use different models, for example Gemini users buying from GPT providers.

Each point is averaged over 100 tasks with five users each, 500 booking goals in total, and placed by its user reward and provider reward. The dashed MAX line indicates the maximum reward achievable.

Why the gap?

Two patterns explain most of this gap: how agents compete for scarce seats, and how provider agents sell.

Individual decisions can undermine collective outcomes

Agent A booked the Delta seats, so Agent B settled for a pricier United trip. A coordinated allocation raises user reward from 0.88 to 0.93 and provider reward from 0.40 to 0.93.

Agents are good buyers but poor sellers

Provider agents could hold the fare, offer another cabin or add paid services. Instead, every booking received the full 30% discount, while customers spent only about half their budgets.

Does a pricier provider agent help?

Users may run their agents only now and then, but a provider agent serves many users, so small differences in cost per request add up. We fix the users' model and compare the inference cost per task of each provider model with the reward of both sides, under scarce and abundant supply. Each dot is one provider model.

Provider inference cost is about twice as high under scarce supply as under abundant supply. Gemini Flash providers are the cheapest in every group, with no consistent loss in either reward. With Astra users, both Gemini Flash providers beat Opus 5 on both rewards at a much lower cost. A higher provider inference cost does not consistently bring a higher reward for either side.
